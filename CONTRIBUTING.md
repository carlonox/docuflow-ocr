# Contributing

Thanks for considering contributing to DocuFlow. This project is small,
focused, and the bar for merging is high — which keeps the codebase honest.

## Ground rules

- The framework is a library, not an app: no web UI, no cloud accounts, no
  hardcoded document formats.
- No real personal data in tests or fixtures. Ever. Fixtures must be
  generated by `scripts/generate_sample_docs.py`.
- No claims in docs that the code doesn't back up. If you can't demonstrate
  it, don't state it.
- Type hints and docstrings are required for every public function.

## Getting started

```bash
git clone https://github.com/carlonox/docuflow-ocr.git
cd docuflow-ocr
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python scripts/generate_sample_docs.py --output tests/fixtures
pytest tests/
```

## What to work on

- Bugs in the cascade or learning subsystems (with a failing test).
- New providers behind the existing `AbstractOCRProvider` interface.
- Preprocessing variants (binarization, deskew, denoise) with benchmarks.
- Documentation corrections.

## Pull request checklist

- [ ] Tests pass (`pytest tests/`)
- [ ] New code has type hints and docstrings
- [ ] No real personal data, no credentials, no synthetic-looking claims
- [ ] CHANGELOG.md updated under `[Unreleased]`
